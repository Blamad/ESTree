# T02 — Characterization tests of the legacy solver and params loader

**Depends on:** T01 · **Unblocks:** T03 · **Size:** M · **Branch:** `task/T02-characterization-tests`

## Goal

Freeze the *current* observable behavior of `LindenmayerTreeParams` (loading) and
`LindenmayerTreeSolver::generateTreeProduction` (rewriting) as golden tests, **before** any
refactor, so T03/T04 can prove they preserved it — and so known bugs are documented, not hidden.

## Why

There are zero tests. The rewriter will be rewritten (T04) and the loader moved (T03). Without a
golden record there is no way to tell a regression from an intentional fix.

## Context to read

- `ESEngine/ESTree/Models/Tree/LindenmayerTreeParams.{h,cpp}`, `LindenmayerTreeSolver.{h,cpp}`
- `Resources/LindenmayerRules/*.json` and `legacy/*.l`
- `docs/architecture/overview.md` → *Rule syntax*, *Suspected defects*

## Scope

In:
1. A test executable `legacy_characterization_tests` compiled from the **unchanged** legacy sources `LindenmayerTreeParams.cpp` and `LindenmayerTreeSolver.cpp` (+ Boost headers/libs, glm, rapidjson as the legacy code needs). It must not link any engine/GL code. If a legacy header drags in engine headers, add a *test-local shim* (in `tests/legacy_characterization/shims/`) rather than modifying legacy sources.
2. Loader characterization — for every file in `Resources/LindenmayerRules/*.json` and `legacy/*.l`: loads without throwing; assert `axiom`, `depth`, `initialLength`, `initialRadius`, `angle` (radians), number of rules per symbol, `customParameters`, and the **substituted production text** of each rule. Store the expectations as golden data in `tests/golden/params/<file>.txt` (plain text, one `key=value` per line) generated by a small dump helper in the test directory, then reviewed by eye.
3. Solver characterization — for each rule file whose rules have no `probability` < 1 and a single production per symbol (**deterministic**; list them in `tests/golden/solver/README.md`), store the production string at depth 0,1,2,3 (and the file's own depth if the length ≤ 200 000 chars, else only its length + a hash) in `tests/golden/solver/<file>.dN.txt`.
4. Stochastic rules (`randomTree*.json`, etc.): assert only *properties*: production length > 0, characters ⊆ the alphabet implied by rules ∪ interpreter symbols, brackets balanced, repeated runs terminate. No exact strings.
5. Known bugs: for each suspected defect in `docs/architecture/overview.md` that you can confirm with a minimal input, add a test named `KNOWN BUG: <summary>` asserting the **current (wrong) behavior**, and list it in `tests/golden/KNOWN_BUGS.md` with the expected correct behavior. T03/T04 will flip these.
6. A `tests/golden/README.md` explaining how to regenerate goldens (`legacy_characterization_tests --regenerate`, off by default) and the rule "goldens change only with a `DECISIONS.md` entry".

Out of scope: modifying legacy sources, fixing bugs, the interpreter/mesh generator (needs GL types), new rule files.

## Owned files

`tests/legacy_characterization/**`, `tests/golden/**`, a block in `tests/CMakeLists.txt`.

## Acceptance criteria

1. `ctest` passes with the new target; running it twice yields identical results (no hidden randomness in the deterministic goldens).
2. Golden files exist for **every** shipped rule file (params) and for every deterministic one (solver); the list in `tests/golden/solver/README.md` explains each exclusion.
3. `git diff` shows no change under `ESEngine/` (legacy code untouched).
4. `KNOWN_BUGS.md` lists each confirmed defect with a reproducing input and the intended fix owner (T03/T04/T05).
5. `REPORT.md` lists any defect you suspected but could not reproduce.

## Verification

Fully automated.

## Notes / risks

- The solver's RNG is a static seeded from `time(0)`; deterministic rules never draw from it in effect, but selection still calls it — confirm that output is stable over 20 repeated runs.
- `std::to_string(float)` output is locale-independent in the C locale; do not call `setlocale`.
- If depth-N production explodes (e.g. > 50 MB), store length + FNV-1a hash only.
