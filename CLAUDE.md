## What this project is

ESTree is a hand-written OpenGL game engine (C++, Windows-first) whose main purpose is generating
trees with Lindenmayer systems (parametric, stochastic, with tropism). It started as a master's
thesis project (2017–2020). The code is being modernized **without replacing the engine**; the
tree-generation logic is being isolated into a standalone module (`treegen`) so it can be split
out of the engine later.

Reply to the user in **Polish**. Code, comments, commit messages and docs are in **English**.

## Repository layout

| Path | What lives there |
|---|---|
| `ESEngine/Engine/` | Engine layer: `Core`, `GameObject` (components), `Manager`, `Scene`, `UI` (in-game console) |
| `ESEngine/GraphicEngine/` | Thin OpenGL layer: window (GLFW), renderer, shaders, VAO, framebuffers, input |

| `ESEngine/ESTree/Models/Tree/` | **Legacy** Lindenmayer pipeline (`Lindenmayer*` classes). Being replaced by `treegen` |
| `ESEngine/TreeGen/` | **Target** engine-independent tree generator, static lib `treegen` (T03: `Error`, `Rng`, `Module`, `TreeParams`, loaders; rewriter/turtle/geometry follow in T04–T06) |
| `Resources/` | Shaders, textures, fonts, `LindenmayerRules/*.json` (+ `legacy/*.l`) |
| `Vendor/` | Git submodules: glfw, glad, glm, bullet3, freetype2, rapidjson, stb. **Do not edit** (only T12 may bump them) |
| `docs/` | Plan, architecture notes, per-task directories (see below) |
| `build/` | Generated by CMake (git-ignored). Never commit it |

Include root is `ESEngine/` (e.g. `#include "Engine/GameObject/Mesh.h"`).
Resource paths are relative to the working directory (`Resources/...`); `setup.bat` symlinks
`Resources` into `build/`.

## Build and test

Requires CMake ≥ 3.21 and `BOOST_LIB` (env) pointing at Boost 1.72 (`Includes/`, `Libs/`) until
Boost is removed (T09/T13). Machine-specific paths (CMake/Ninja location, compilers, Boost) are in
`CLAUDE.local.md` (git-ignored). Verified in T00 (preset `vs2019`, MSVC v142, CMake 4.4.4):

```bash
cmake --preset vs2019                      # configure into build/vs2019
cmake --build --preset vs2019-debug --parallel     # or vs2019-release
# run (working directory must contain Resources/; setup.bat links it)
cd build/vs2019 && ./Debug/ESTree.exe --help
# tests (exist from T01 on)
ctest --test-dir build/vs2019 -C Debug --output-on-failure
```

Faster alternative (Ninja + newest MSVC 19.51, verified Debug, ~1.5 min clean). Needs the MSVC
environment, so wrap each command with `scripts\msvc-env.cmd` (set `VCVARS64` to override the
`vcvars64.bat` path):

```bash
cmd //c "scripts\\msvc-env.cmd cmake --preset ninja-msvc"
cmd //c "scripts\\msvc-env.cmd cmake --build --preset ninja-msvc-debug"
```

Presets: `vs2019` (verified Debug+Release), `ninja-msvc` (verified Debug), `vs2026` (does not
configure on this machine: CMake can't see the VS 2026 Build Tools instance). Preset names are in
`CMakePresets.json`. A clean `vs2019` build takes ~5 min (Bullet is the long pole); incremental
builds of the app target take seconds. Baseline numbers: `docs/tasks/T00-build-baseline/notes/baseline.md`
(143 unique `/W4` project warnings — don't add new ones).

Agents cannot judge rendered images. They *can* smoke-launch the exe on the owner's desktop (see
`CLAUDE.local.md`: `Start-Process`, wait ~20 s, expect "still running", no crash event, expected log
lines), which catches crashes and hangs. Anything about what is drawn is **"needs human
verification"**: say so explicitly in `REPORT.md` and give the exact steps (scene number, console
command) the user should run. Never claim visual correctness. The engine only works on the NVIDIA
GPU of the owner's Optimus laptop (the Intel iGPU driver crashes, see `docs/BACKLOG.md`).

## Architecture rules (enforced)

1. **`treegen` is pure.** Code under `ESEngine/TreeGen/` may include only the C++ standard
   library, `glm`, and `rapidjson`. It must never include `Engine/`, `GraphicEngine/`, `glad`,
   `GLFW`, Bullet, FreeType, or `boost/`. T03 adds a CTest that greps for this; keep it green.
2. **Dependency direction:** `ESTree` app → `Engine` → `GraphicEngine`; `ESTree/Models/Tree`
   (adapter) → `treegen`. `treegen` depends on nothing in the repo.
3. **Strangler migration.** Old `Lindenmayer*` classes keep their public API and delegate to
   `treegen` until T07 deletes them. Never leave the engine unbuildable between tasks.
4. **Behavior-preserving unless the brief says otherwise.** Refactors must not change generated
   trees. Intentional changes (bug fixes) are listed in the task brief and logged in
   `docs/DECISIONS.md`.
5. **Determinism.** New code takes an explicit `uint32_t seed`; no global RNG, no `time(0)`
   seeding inside the library.

Full contract: `docs/architecture/treegen-design.md`. Current state: `docs/architecture/overview.md`.

## Code style

- Match the surrounding code. Existing engine code: **tabs**, `PascalCase` types,
  `camelCase` members/methods, K&R braces, `#ifndef` guards in older headers.
- New `treegen` code: C++17, `#pragma once`, namespace `treegen`, tabs and `camelCase` like the
  rest of the repo (no `snake_case`). No Boost, no raw `new`/`delete`, no `using namespace`
  in headers.
- Prefer `std::` replacements for Boost (`<random>`, `<thread>`, `<chrono>`, `<filesystem>`).
- Comments only where the *why* is non-obvious. Don't add banner comments or restate code.
- Do not reformat files you are not otherwise changing (keeps diffs reviewable).

## Working on a task

Tasks live in `docs/tasks/Txx-slug/`. Workflow, templates and rules: `docs/tasks/README.md`.
Short version:

1. Read this file, `docs/PLAN.md`, `docs/architecture/*`, then `BRIEF.md` in your task directory.
2. Write `PLAN.md` in your task directory **before touching code** (use the
   `superpowers:writing-plans` skill; the brief states goal and acceptance criteria, you decide
   the steps). Commit it.
3. Work on branch `task/Txx-slug` (ideally in a git worktree). TDD where the brief calls for tests.
4. Stay inside the files your brief lists as owned. Touching anything else → note it in `PLAN.md`
   first and keep the change minimal.
5. Finish with `REPORT.md` (what changed, evidence = command + output, deviations, follow-ups,
   what needs human verification). Use `superpowers:verification-before-completion`: no
   "done"/"passing" without having run the command in this session.
6. Don't edit `docs/PLAN.md` status or other tasks' files; the orchestrating session does that.
   Record new design decisions in `docs/DECISIONS.md` (append only).

## Git

  until the owner decides the results are good and merges `modernization` into it. Task branches
  `task/Txx-slug` are created from `modernization` and merged back into it (never into `master`).
  Remote: `origin` = `Blamad/ESTree` (GitHub).
- Never commit to `master` directly; never force-push; never skip hooks.
- Small, focused commits. Message format: `T03: add treegen CMake target` (task id prefix).
- Do not commit `build/`, IDE files, generated binaries, or machine-specific paths.
- Submodules in `Vendor/` are pinned; don't change their commits outside T12.
